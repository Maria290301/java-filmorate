Filmorate: работа в команде (спринт 13)
На этом этапе мы работали над Filmorate в составе команды. Целью спринта стало превращение приложения из сервиса рекомендаций в социальную платформу, где пользователи могут взаимодействовать друг с другом: оставлять отзывы, делиться любимыми фильмами, следить за действиями друзей и находить интересный контент через расширенный поиск.

📌 Цели спринта
По итогам обсуждения с проджектом и анализа брифа, мы выделили следующие ключевые фичи, которые предстояло реализовать:

Отзывы на фильмы

Поиск фильмов по названию и описанию

Общие фильмы между пользователями

Персональные рекомендации

Лента событий (feed)

Фильмы по режиссёрам

Популярные фильмы по жанрам и годам

Удаление фильмов и пользователей

Некоторые фичи были отмечены как «дополнительные» — на их реализацию мы перешли только после завершения основной части.

🛠 Как мы организовали работу
Мы распределили задачи по фичам между участниками команды.

Каждому досталось по 2–3 задачи — с учётом сложности, времени и личного интереса.

Для каждой задачи был определён объём (в сторипойнтах) и исполнитель.

Использовалась канбан-доска GitHub Projects, где каждая задача проходила следующие статусы: To do → In progress → Team code review → Practicum code review → Completed.

Ревью задач внутри команды проводили взаимно — это позволило выявлять ошибки до отправки на итоговую проверку.

🔍 Мой вклад в проект
В рамках командной разработки я реализовала следующие задачи:

✅ Функциональность: Отзывы на фильмы (/reviews)
Реализовала сущность Review и соответствующую таблицу в базе данных.

Добавила эндпоинты:

POST /reviews — создание отзыва

PUT /reviews — обновление

DELETE /reviews/{id} — удаление

GET /reviews/{id} — получение по ID

GET /reviews?filmId=... — список отзывов к фильму

Добавила функциональность лайков/дизлайков для отзывов.

Написала SQL-скрипты и интеграционные тесты на ReviewDbStorage.

✅ Функциональность: Лента событий (/feed)
Создала сущность Event и таблицу events, где логируются все действия пользователя: добавление в друзья, лайки, отзывы.

Реализовала эндпоинт GET /users/{id}/feed, возвращающий события пользователя.

Обеспечила поддержку трёх типов событий: FRIEND, LIKE, REVIEW.

Обновила сервисы и контроллеры, чтобы при каждом изменении состояния сохранялось событие.

Провела покрытие кода unit- и интеграционными тестами.

🧱 Архитектурные решения
Каждая новая фича реализована через сервисный слой — вся логика отделена от контроллеров.

Для работы с БД созданы DAO через JdbcTemplate.

Все зависимости внедряются через @Autowired и @Qualifier, чтобы обеспечить гибкость при смене реализации (в том числе для тестов).

Валидация входных данных реализована через аннотации и проверку в сервисах.

Для каждого нового функционального блока реализованы собственные DTO и мапперы.

📦 Интеграция в проект
Все фичи были добавлены в единую кодовую базу с учётом командных веток. Я регулярно делала pull из основной ветки, чтобы минимизировать конфликты с другими задачами.

После завершения задач я выносила пул-реквесты, добавляла описание изменений и тестовые кейсы, а также проводила ревью задач других участников команды.

📊 Проверка и тестирование
Все реализованные мною фичи прошли проверку через Postman (коллекция sprint.json) и автоматические тесты в GitHub Actions.

Для работы с базой использовалась H2. Я написала отдельные тесты с использованием @JdbcTest, @AutoConfigureTestDatabase и @Import.
