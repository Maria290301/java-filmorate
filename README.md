# java-filmorate
Filmorate — сервис для оценки и хранения фильмов
Это бэкенд-приложение на Spring Boot, которое я разработала в рамках учебного проекта. Основная задача — реализовать REST-сервис, который позволяет пользователям добавлять фильмы, выставлять оценки и формировать список рекомендованных к просмотру.

В текущем спринте я сосредоточилась на создании базовой структуры приложения, REST-контроллеров и валидации данных.

Что реализовано
Архитектура проекта
Использован Spring Boot для создания каркаса приложения.

Реализованы две основные модели:

Film — сущность фильма;

User — сущность пользователя.

Каждая сущность содержит набор атрибутов, отвечающих за описание и идентификацию объекта (id, name, description, email и др.).

REST API
Созданы два контроллера:

FilmController:

POST /films — добавление фильма;

PUT /films — обновление фильма;

GET /films — получение списка всех фильмов.

UserController:

POST /users — создание пользователя;

PUT /users — обновление пользователя;

GET /users — получение всех пользователей.

Все эндпоинты реализованы согласно REST-подходу. Возвращаемые статусы соответствуют типу операции (201 Created, 200 OK и др.).

Хранение данных
На текущем этапе все данные хранятся в памяти приложения (In-Memory Storage) без использования базы данных. Это упростило отладку логики на раннем этапе.

Валидация данных
Добавлена проверка входных данных с помощью аннотаций javax.validation. Обрабатываются следующие условия:

Для Film:

name — не пустое;

description — не более 200 символов;

releaseDate — не ранее 28.12.1895;

duration — положительное число.

Для User:

email — содержит @ и не пустой;

login — не пустой и не содержит пробелов;

name — может быть пустым (тогда используется login);

birthday — не в будущем.

Ошибки валидации возвращаются с подробными описаниями.

Логирование
С помощью SLF4J настроено логирование:

Запись успешных операций добавления и обновления.

Отдельные сообщения об ошибках валидации, с указанием причины.

Тестирование
Написаны unit-тесты для проверки моделей Film и User на корректность валидации.

Учтены граничные случаи (например, пустое имя, дата в будущем и т. д.).

Для тестирования API использовалась коллекция запросов Postman.
